Generated by `tools/calc_replay.py`. Per-lot detail: `lots.csv`.

> **Data warning: this export looks column-shifted, so factor-level results below are not reliable.** `HARVEST_FACTOR_4` equals `DESIRED_DENSITY` on 1689 of 1714 lots, `HARVEST_FACTOR_2` is set on only 22 of 8149, and `CONTAINER_FACTOR_1/2` hold cell counts while `CONTAINER_FACTOR_3` holds 1-5. Re-run with `--source` pointing at the Access backend.

## Data used

- Agreement lots: Oracle-era export `seed/NMIS_AGREEMENT_LOTS.json` (no --source given or table missing).
- Begin container: Access XML `seed/access/*/species_product_cycles.xml`.
- Cells per container: `project_pack/13_reference_grow_units.csv` (NMIS_UNITS not supplied).
- Factor operators: NMIS_FACTOR_CODES not supplied, so every harvest and container factor is treated as `*` (multiply).
- Lots read: 8149. Replayed: 6365.
- Skipped, propagule / native (N, NSP): legacy uses bed-feet-per-acre, not seed (SP-14): 1779
- Skipped, no TOTAL_REQUEST: 5
- Lots with a begin container (and so cells per container): 22 of 6365. Bareroot lots without one use 4 cells per container (true of every bareroot grow unit). Other lots without one are compared on seed only.
- Gaps are measured only on lots with harvest factor 1 and test data (germ, purity, seeds/lb) present: 1703 of 6365. On the rest a gap would only reflect missing inputs.
- GrowHub-only inputs: `pastInventoryPerformance` blank (counts as 100%). `cellsFilled` and `containerSurvival` both 100, so their ratio is 1. Migration maps none of the three, and a blank `cellsFilled` would make GrowHub space 0.
